# 07 · Validation & API contracts

## One schema, three jobs

NestJS 12 supports [Standard Schema](https://standardschema.dev) natively. Each **Zod** schema gives you all of these:

1. **Runtime validation.** A global pipe validates every parameter declared with `{ schema }`.
2. **The TypeScript type**, via `z.infer`.
3. **API reference.** The OpenAPI document is generated from the same schema.

```ts
// presentation/orders.schemas.ts
export const createOrderSchema = z
  .object({
    items: z
      .array(z.object({ productId: z.uuid(), quantity: z.number().int().min(1).max(100) }))
      .min(1),
    note: z.string().max(500).optional(),
  })
  .meta({ id: 'CreateOrderRequest' }); // → named component in OpenAPI
export type CreateOrderRequest = z.infer<typeof createOrderSchema>;
```

```ts
// presentation/orders.controller.ts
@Post()
@ApiCreatedResponse({ standardSchema: orderResponseSchema })
create(@Body({ schema: createOrderSchema }) body: CreateOrderRequest) { … }

@Get()
list(@Query({ schema: listOrdersQuerySchema }) query: ListOrdersQuery) { … }

@Get(':id')
get(@Param('id', { schema: z.uuid() }) id: string) { … }
```

- Parsed values **replace** the raw input. Coercion, defaults, `.trim()` and transforms are applied before your handler runs.
- **Unknown keys are stripped** (Zod's default `z.object` behaviour). Use `.strict()` to reject them instead.
- Query strings are always strings. Use `z.coerce.number()`, or the shared `paginationQuerySchema`.
- A parameter **without** `{ schema }` is not validated, so always add one.

## Responses

- Controllers return **presented DTOs**, built by `toXResponse(entity)` functions that pick fields explicitly. Never return entities or DB rows, because that can leak fields like `passwordHash` or internal flags.
- Document each response with `@ApiOkResponse({ standardSchema: xResponseSchema })` (or `ApiCreatedResponse`, and so on).
- Dates are ISO-8601 strings in UTC.
- Successful responses are **not wrapped** in an envelope. A resource is the body. Collections use `{ items, meta }`.

### Pagination

```ts
// query: ?page=2&limit=20  (limit ≤ 100)
export const listOrdersQuerySchema = paginationQuerySchema.extend({ status: z.enum([...]).optional() });

// service/repository return Page<T>; controller maps it
return mapPage(await this.orders.list(query), toOrderResponse);
```

```json
{ "items": [ … ], "meta": { "page": 2, "limit": 20, "totalItems": 135, "totalPages": 7 } }
```

For very large or fast-moving tables, use keyset (cursor) pagination. See [14 – Recipes](14-recipes.md#cursor-pagination).

## Versioning

URI versioning: `/api/v1/...`. Each controller declares its version:

```ts
@Controller({ path: 'users', version: '1' })
```

To introduce a breaking change:

1. Add a **v2 controller** (or a method with `@Version('2')`) next to v1. Reuse the same service.
2. Mark v1 deprecated in the API reference (`@ApiOperation({ deprecated: true })`) and announce a sunset date.
3. Delete v1 after clients have migrated.

These changes are **non-breaking** and don't need a new version: adding optional request fields, adding response fields, adding endpoints, adding error codes.

## API reference (Scalar + OpenAPI)

| What               | Where                                                  |
| ------------------ | ------------------------------------------------------ |
| Interactive docs   | `GET /docs` ([Scalar](https://scalar.com))             |
| OpenAPI 3 document | `GET /docs/openapi.json`                               |
| Document on disk   | `pnpm openapi:export [file]` → `openapi.json`          |
| Switch             | `API_DOCS_ENABLED` (default: on, except in production) |
| Code               | `src/core/openapi/openapi.ts`                          |

The document is generated by `@nestjs/swagger` from the controllers and Zod schemas. Scalar renders it. Swagger UI is not used ([ADR 0006](adr/0006-scalar-api-reference.md)).

Using the page: pick an endpoint, press **Test Request**, and paste an access token into the **Authentication** box to call protected routes. Every operation shows request samples for curl, fetch and other clients.

### Documenting an endpoint

```ts
@ApiTags('Orders') // sidebar group
@ApiProblemResponses() // 400, 401, 429, 500 for every route of the controller
@Controller({ path: 'orders', version: '1' })
export class OrdersController {
  @Get(':id')
  @ApiOperation({ summary: 'Get an order', description: 'Longer text, Markdown allowed.' })
  @ApiOkResponse({ standardSchema: orderResponseSchema })
  @ApiProblem(404, '`ORDER_NOT_FOUND`') // one line per specific error, naming the stable code
  get(@Param('id', { schema: z.uuid() }) id: string) { … }
}
```

- **Every endpoint** gets `@ApiOperation({ summary })` and a success response with `standardSchema`. An e2e test (`test/api-docs.e2e-spec.ts`) fails if an operation has no summary or tag.
- **Every error a client should handle** gets `@ApiProblem(status, 'CODE: when it happens')`. `@Roles()` adds the 403 by itself.
- **Public routes:** `@Public()` removes the lock icon and the "missing token" response in the reference automatically.
- Name schemas with `.meta({ id: 'Order' })` so they appear under **Models**. Add `.describe('…')` to fields that need explaining.
- To describe a sidebar group, add the tag to `TAGS` in `openapi.ts`. The intro text of the page is `DESCRIPTION` in the same file.

### Generating clients

```bash
pnpm openapi:export                                   # writes ./openapi.json (no server, no database needed)
npx openapi-typescript openapi.json -o client/api.d.ts
```

CI uploads `openapi.json` as a build artifact on every run. Diff it between a PR and `main` to spot breaking contract changes.

### Security of the docs page

- `/docs` and `/docs/openapi.json` need no token when enabled, and they describe the whole API. They are **off in production** by default. If you turn them on there, restrict access at the network level.
- The page is served with its own nonce-based Content-Security-Policy. Enabling docs does not relax the policy of the API itself.
- The Scalar script is loaded from jsDelivr, pinned to an exact version (`SCALAR_BUNDLE_URL`). Telemetry and the hosted Scalar features are disabled.

### Serving the Scalar bundle yourself

For air-gapped environments, or to drop the CDN dependency:

1. `pnpm add @scalar/api-reference` and serve its `dist/browser/standalone.js` from a route such as `/docs/scalar.js` (`res.sendFile`).
2. Set `SCALAR_BUNDLE_URL = '/docs/scalar.js'` and add `'self'` to `script-src` in the docs CSP if you drop the nonce.
3. Remove `https://fonts.scalar.com` from the docs CSP and pass `withDefaultFonts: false` to `apiReference()`.

## Common Zod snippets

```ts
z.email().max(320);
z.uuid();
z.string().trim().min(1).max(100);
z.enum(['draft', 'published']);
z.coerce.number().int().min(0);
z.iso.datetime(); // ISO string
z.coerce.date(); // accepts ISO string → Date
z.string().regex(/^[A-Z]{3}$/); // e.g. currency
schema.partial(); // PATCH bodies
schema.refine((v) => v.a !== v.b, { path: ['b'], message: 'must differ' });
z.discriminatedUnion('type', [a, b]); // polymorphic payloads
```
